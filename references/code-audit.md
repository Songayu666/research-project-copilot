# 科研代码审计

在根据现有代码生成方案、论文图或汇报结论前执行。

## 1. 建立运行链路

- 找到主入口、配置文件、数据路径和输出文件。
- 画出真实调用关系；未被入口调用的脚本标为“独立/未接入”。
- 核对结果文件的修改时间、变量和当前代码是否对应；无法证明时标为“版本待核实”。

## 2. 检查科学风险

- 单位、坐标系、符号和维度是否一致。
- 是否存在显示缩放、归一化、反归一化或人为倍率。
- 是否存在“原始参数”被“调参值”覆盖。
- 数据划分、随机种子、训练/验证/测试是否存在泄漏。
- 基线、损失函数、评价指标和停止条件是否定义完整。
- 数值求解器、步长、容差、边界条件、初值和模态截断是否有依据。
- 矩阵正定性、秩、收敛性和异常值处理是否经过检查。

## 3. 只提取可支持的结论

按 `evidence-contract.md` 标记关键结论。优先直接从数据重新计算指标；只存在绘图或注释时，不将其升级为已验证。

## 4. 输出审计摘要

至少列出：入口与调用链、可复现步骤、已验证结果、待核实问题、对汇报结论的影响。若风险会改变核心结论，先询问用户；若用户要求开始，则在成果中显著说明边界。
