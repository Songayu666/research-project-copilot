# 零基础研究方案 Markdown 规范

文档建议结构如下；按任务删减，不为凑结构制造内容。

1. 项目一句话说明：要解决什么问题，为什么值得做。
2. 最终目标：用可观察、可验收的语言描述。
3. 已有材料：数据、代码、论文、设备与限制。
4. 核心概念：首次出现即用白话解释，附项目内例子。
5. 整体路线：用编号步骤说明“输入 → 处理 → 输出 → 验证”。
6. 方法细节：每一步写“做什么、为什么、怎么做、产出什么”。
7. 若有神经网络：输入/输出、张量形状、逐层表格、损失函数、训练与推理流程。
8. 基线与改进点：表格对比原始方法和新方法，避免只写“更好”。
9. 实验设计：数据划分、指标、对照、消融、重复次数和随机种子。
10. 实施指南：环境、依赖、入口命令、文件结构和预期输出。
11. 常见问题：至少覆盖数据路径、维度不匹配、显存/内存和结果不复现。
12. 状态表：已确认事实、当前假设、待补材料、下一步。

写作规则：短句优先；一个段落只解释一个概念；代码块前说明目的、代码块后说明结果；缩写首次出现写出中文含义与英文全称；不要假设读者知道命令行、张量、训练集或指标的含义。
